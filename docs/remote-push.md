# Отправка статистики на свой aw-server

Форк официального aw-android. Приложение работает как обычно: собирает статистику в свою
локальную базу и показывает её в своём web UI. Добавлено одно: раз в 15 минут события этого
телефона копируются на self-hosted aw-server (`http://100.83.127.94:5600`, сервер доступен
только из tailnet). Там телефон появляется отдельным хостом рядом с Windows-ПК.

## Как работает

`RemotePushWorker` — периодическая задача WorkManager (раз в 15 минут, только при наличии сети).
Её ставит в очередь `BackgroundService` при старте. Дальше WorkManager сам перезапускает её,
в том числе после перезагрузки телефона. Каждый запуск:

1. Забирает свежие события из системной статистики Android в локальную базу. Без этого они
   попадают туда только раз в час или при открытии приложения.
2. Для каждого локального бакета этого устройства (`aw-watcher-android`, `-unlock`, `-web`,
   `-media`) создаёт на сервере бакет `<бакет>_<hostname>`, например
   `aw-watcher-android_pixel_8`. Это то же соглашение об именах, что у десктопных вотчеров,
   поэтому несколько телефонов не смешаются. Hostname берётся из имени устройства в настройках
   Android.
3. Отправляет на сервер локальные события, которые начинаются не раньше последнего события,
   уже лежащего на сервере.

**Курсор — сам сервер.** Отдельно «что уже отправлено» нигде не хранится: каждый раз
спрашивается последнее событие серверного бакета. Поэтому прерванная или повторная отправка
не создаёт дублей, а после долгого отсутствия связи (Tailscale выключен) доотправляется всё
накопленное. Первая отправка переносит всю локальную историю.

**Последнее событие заменяется по id.** Самое новое событие ещё растёт: текущая сессия
приложения или вкладка браузера удлиняются между запусками. Поэтому его локальная версия
перезаписывает серверную копию по её id (`INSERT OR REPLACE`), а всё, что новее, просто
вставляется. Heartbeat-слияние для этого не годится: оно склеивает события, только если `data`
совпадает побайтно, а при любом расхождении каждые 15 минут добавлялся бы дубль. Локальный `id`
у событий перед отправкой вырезается, иначе сервер перезаписал бы свои события с такими же
номерами (например, события Windows).

Бакеты, которые aw-sync затянул с других устройств, не отправляются: у них чужой hostname.

## Ограничения

- Телефон должен быть в tailnet (приложение Tailscale включено), иначе запуск тихо завершается
  ошибкой, и всё отправится в следующий раз.
- Android откладывает фоновые задачи в режиме Doze, поэтому на спящем телефоне интервал
  бывает больше 15 минут.
- Адрес сервера задаётся при сборке: `./gradlew assembleStandardDebug -PremoteServerUrl=http://host:5600`
  (пустое значение отключает отправку). Для нового хоста нужно разрешить HTTP в
  `mobile/src/main/res/xml/network_security_config.xml`.

## Сборка

Ветка `remote-push` основана на теге `v0.14.4b1`. Нативные библиотеки (`libaw_server.so` со
встроенным web UI и `libaw_sync.so`) не собираются из Rust, а берутся из официального APK этого
релиза. Тогда их JNI-интерфейс гарантированно совпадает с Kotlin-кодом.

```sh
gh release download v0.14.4b1 -R ActivityWatch/aw-android -p 'aw-android-arm64-v8a.apk'
unzip -o -j aw-android-arm64-v8a.apk 'lib/arm64-v8a/*' -d mobile/src/main/jniLibs/arm64-v8a
./gradlew assembleStandardDebug
# mobile/build/outputs/apk/standard/debug/mobile-standard-debug.apk
```

Debug-сборка ставится рядом с официальным приложением (`net.activitywatch.android.debug`), но
локальный сервер у обоих на порту 5600, поэтому официальное приложение лучше удалить.
